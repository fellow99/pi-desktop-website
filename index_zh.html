开源 · MIT · 非官方的 Pi 桌面壳

让 Pi agent harness 在桌面安家。

Pi Desktop 把上游的 Pi Web UI —— 原样不改 —— 装进 Windows、macOS、Linux 与 HarmonyOS 的原生外壳里。Pi 宿主和它的 Next.js 服务器跑在应用自身进程内，窗口从同一个源加载这套 UI：没有云端中转、没有 CORS、没有登录页，PATH 里也不需要 pi 二进制。你现有的会话、凭据与扩展照样可用。

$ 为什么要原生外壳

为什么要原生外壳

完整的 Pi 体验 —— 但没有那个浏览器标签页。

100% 上游 Pi 与 Pi Web —— SDK 与 UI 原样运行。

Pi SDK 与 Pi Web UI 原样运行，壳只负责装配。桌面版 0 条补丁，上游的改进可以直接跟上，不必维护一个 fork 去 rebase。Electron on HarmonyOS 版有 2 条登记补丁；HarmonyOS 版以 5 条幂等可逆的补丁文件在构建期施加、随即回退，所有上游工作树始终保持 pristine。

本地优先，进程内。

Pi 宿主与它的 Next.js 服务器跑在应用自己的主进程里 —— 没有 sidecar、没有孤儿 Node 进程 —— UI 从同一个源加载。没有任何东西经云端中转，也没有需要你粘贴密码的登录页。

一个桌面公民。

系统托盘、由尾随会话日志驱动的原生通知、单实例唤回、记住的窗口尺寸与位置，外链交给系统浏览器打开。

与 pi CLI 共用一套环境。

默认落在 ~/.pi/agent，所以会话、凭据、扩展与 MCP 配置就是你终端里已经在用的那一套。需要隔离时，可以在设置里切到应用私有目录。

Pi Desktop

Electron · Windows · macOS · Linux
  • Electron 43.7.9（Node 24.21.0 / Chromium 150）：pi-web 的 Next.js 服务器跑在主进程内，不是 sidecar。
  • 随机 loopback 端口配宿主生成的随机强密码 —— 凭据由壳注入，登录页永不出现。
  • 随包分发 pi-dist.tar.gz，首启解压到 userData，之后按 SHA-256 marker 跳过。
  • 安装包：Squirrel（Windows）、DMG（macOS）、deb / rpm / zip（Linux）—— 未签名，SmartScreen 与 Gatekeeper 会拦。
  • 状态：v0.12.1 · Windows 打包态端到端已验收；macOS 与 Linux 待验证。

Pi Desktop · HarmonyOS 版

ArkWeb + 进程内 Node · 2in1 与平板
  • 不带 Chromium、也不带 Electron：ArkTS 宿主 + ArkWeb 加载本地 pi-web 服务，而该服务跑在应用进程内的真 Node.js 运行时上（@fellow99/node-bridge：dlopen + node::Start）。
  • 与 Electron on HarmonyOS 版同一个「进程内宿主 + 同源加载」形态 —— 差别在由谁提供 Node 运行时，且包体小得多。
  • 宿主能力显式且可归因：权限（带下一步指引）、文件夹 / 文件选择器、通知，以及 ArkTS↔Node 的文件信箱桥。
  • 真机验证：HUAWEI MateBook Pro（HAD-W24），HarmonyOS API 26；能力对齐逐条记录在 docs/001-能力复刻评估.md。
  • 已知限制：无终端 / PTY（平台没有 devpts）；真 JIT 需要 ALLOW_WRITABLE_CODE_MEMORY ACL，否则只能 --jitless（WebAssembly 不可用）。
  • 状态：v0.1.0 · 骨架 + Phase 1 能力已真机可用。

Electron-on-鸿蒙 · 2in1 与平板

三个版别合起来覆盖四个桌面平台 —— Windows、Linux、macOS（Electron 版）加 HarmonyOS；HarmonyOS 端有两个独立版别：Electron on HarmonyOS 版（保留 Electron 运行时）与 HarmonyOS 版（ArkWeb + 内嵌 Node 运行时，不带 Electron）。三个独立的、非官方的开源壳，建立在 Pi 与 Pi Web 之上；桌面版无补丁，Electron on HarmonyOS 版有 2 条登记补丁，HarmonyOS 版有 5 条幂等补丁文件。与 Pi 或 Pi Web 作者无隶属关系，也未获其背书。目前均未做代码签名，Windows 上会出现 SmartScreen 提示，macOS 上会被 Gatekeeper 拦下。

$ 工作原理

一个宿主。一个源。零摩擦。

  1. 1

    进程内宿主

    壳在 Electron 主进程里启动 pi-web 的 Next.js 服务器。

  2. 2

    同源 UI

    窗口从这台服务器加载 http://127.0.0.1:<port>/。

  3. 3

    上游数据面

    标准的 Pi Web UI 驱动全部通信：fetch('/api/*') 上行，SSE 下行。

无 CORS · 无自定义协议 · 无登录页。
